## 一条命令启动

在仓库根目录打开PowerShell：

```powershell
& D:/anaconda/envs/dachuang_2026/python.exe -B scripts/run_local.py
```

看到ready=true后访问http://127.0.0.1:5179。按Ctrl+C停止本次服务。后端为http://127.0.0.1:8000，前端通过同源/api代理连接，不需要额外CORS配置；127.0.0.1只表示本机，不是局域网或公网部署地址。

先检查环境或更换端口：

```powershell
& D:/anaconda/envs/dachuang_2026/python.exe -B scripts/run_local.py --check-only
& D:/anaconda/envs/dachuang_2026/python.exe -B scripts/run_local.py --api-port 18080 --web-port 15179
```

启动器显式固定local规则检索、template摘要、API数据源和同源代理，禁用FAISS与运行审计。它不会继承父环境中的LLM/FAISS开关触发收费调用，也不会自动读取/覆盖密钥文件。真实模型发布配置需另行授权验收，不通过修改此启动器偷偷启用。

## 启动与退出行为

1. 检查当前Python模块、Node、已有Vite依赖及教材/图谱/形象资产。
2. 检查127.0.0.1的前后端端口。冲突就退出并提示换端口，不终止占用者。
3. 同步并验证展示资产，失败不启动服务。
4. 启动本轮Python API和Vite，核对/health及/api/health的status=ok、service=zhizheng-sizheng，再输出ready=true。
5. 服务异常退出、Ctrl+C或指定运行时长结束时，只清理本启动器创建且仍存活的进程及其子进程，不枚举关闭其他服务。

每次在outputs/local_runs/<UTC时间>/保存后端/前端/同步日志与runtime.json。记录仅包含允许的模式、URL、解释器和本轮PID，不导出整个环境或密钥。未就绪不能把“进程已创建”当成启动成功。

web/.env.example用于单独运行Vite时参考；一体启动无需复制文件。DACHUANG_API_PROXY_TARGET在Vite服务端配置代理目标，API地址使用VITE_API_BASE_URL=/api。API Base URL拒绝非HTTP(S)、凭证、查询参数和片段，错误不静默降级为Mock。

## 页面错误与恢复

- 连接中断/HTTP失败/超时/空响应/坏JSON：显示请求错误，移除正式回答和讲解入口，保留输入。
- 配置缺失或非法：提示检查启动配置、重启页面服务，详情中保留错误码；不自动改用模拟答案。
- 矛盾或畸形响应：仍由响应边界进入数据契约异常，不能通过重试按钮绕过校验。
- “重试上次查询”只在用户点击后重发上一次已提交的问题、学段与场景快照，不把当前尚未提交的草稿发送出去。编辑、切学段本身不请求。
- 前端45秒停止等待并取消浏览器请求，不保证服务端任务已立即结束。避免在服务繁忙时连续重复提交。
- 未知时空ID、空图谱、缺原文及地图底图失败继续使用相应模块的空/错状态，不能伪造资产或答案。
