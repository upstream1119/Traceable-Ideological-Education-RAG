## 清洗和 citation

正文以 `para_blocks` 为抽取输入，不同时拼接 `preproc_blocks`。`preproc_blocks` 仅独立用于物理页边界核验，因为 `para_blocks` 可能已把下一页正文并入上一页。

删除排版空白与脚注标号；通过块类型和人工核对排除页眉、页脚、页码、目录、扫描水印、脚注正文。样例003的段内枚举标题“再次，设立政治辅导处与辅导员。”由 title 承担，正文从明确日期开始；未改写后续事实。未添加来源之外的史实，也未凭印象修正 OCR。

`citation.doc` 使用正式书名；`section` 使用实际章、节、小标题路径，仅规范空格。已对照 PDF 第201、202、211、212、214页完整相关段落视觉复核；上层第五章与第二、三节标题沿用此前已核验的位置。

本段页码公式：`全书 PDF 实际页 = 局部 page_idx + 200 + 1`。跨页一律填写正文起始物理页，所以三个 page 为 **201、211、214**，不能填主体所在的202页或印刷页码187、197、200。

## 兼容实体类型的最小方案

原 JSONL 保持现有12字段，`entities` 和 `tags` 都是非空字符串列表，不添加类型前缀，不改为对象数组，不修改 configs/schema.yaml。

类型信息保存在独立 `entity_types.jsonl`，每条结构为 `{"chunk_id":"...","entities":[{"name":"...","type":"...","evidence":"正文中的连续原文"}]}`。`name` 必须与该 chunk 的 entities 完全对应，`evidence` 必须能在该 chunk 正文找到。当前类型枚举为 person（人物）、place（地点）、organization（组织）、event（事件）、time（时间），另补 document（文献）和 role（职务角色），避免把文献或辅导员角色强行归为人物/组织。它是此次样例的辅助约定，不是对全项目 schema 的升级。

没有明确人物或地点的 chunk 不强行补齐五类实体。政治辅导员是职务角色，不代表某个具名人物；政治辅导处是组织机构。样例001的朝鲜是正文涉及的支援对象地域，不代表命令签发地点，也不提供猜测坐标。样例002和003没有正文可确认的具体城市，location 全部为 null。

时间只使用原文精度：样例001包括不同日期的同主题指示，start/end 留 null，display 保留月份及命令日期，不把单一日期当作整个教育活动的起点；样例002只给1956年1月，不补成1月1日；样例003明确到1952年9月2日，可填写 start=1952-09-02，end 未知留 null。既有 v1/v2 专项测试的 time.display 等于章节路径是旧批次专用断言，并非基础 schema 要求；本样例使用已有字段表达真实时间，不修改旧批次或旧测试。

张博涵可以按稳定 chunk ID 关联正文、实体和类型依据，但关系三元组仍须以正文为准。不能把实体共现、地点出现或本辅助文件的顺序当作关系成立依据。
