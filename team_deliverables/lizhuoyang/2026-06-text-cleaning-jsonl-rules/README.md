# 文本清洗与 JSONL 标准化交付规范

## 1. 文档用途

本文档用于在新对话中指导文本资料清洗、语义切片和标准化 JSONL 生成。

适用输入包括：

- PDF 原文
- MinerU JSON
- DOCX 文档
- OCR 文本
- 其他具有明确来源和章节结构的文本资料

目标是生成可供检索、RAG、知识图谱和汇报展示使用的中间数据，同时保证正文可回查、引用可验证、字段结构统一。

## 2. 仓库目录边界

必须遵守以下目录规范：

- `src/`：核心代码、正式 ETL 和后端业务代码。
- `data/raw/`：系统正式使用的原始资料。
- `data/processed/`：系统运行会读取的正式 JSONL 数据。
- `tests/`：正式测试、质量测试和验收集。
- `docs/`：正式项目文档。
- `team_deliverables/lizhuoyang/YYYY-MM-任务名/`：说明文档、汇报素材、草稿、交付记录和非核心辅助脚本。

禁止事项：

- 不把正式代码放入 `team_deliverables/`。
- 不把系统运行依赖的唯一数据文件放入 `team_deliverables/`。
- 不随意移动或覆盖已有正式数据。
- 不修改与当前任务无关的 `src/`、`data/`、`tests/` 文件。
- 汇报材料不得散放在 `docs/` 根目录。

如果生成的是正式数据，输出到 `data/processed/`；如果只是样例或汇报副本，必须明确其用途，并避免让系统把副本当成正式数据读取。

## 3. 推荐处理流程

### 3.1 明确任务边界

开始前确认：

1. 输入文件及其来源。
2. 本批处理的章节、页码或内容范围。
3. 输出文件名和输出目录。
4. 是新建文件、追加数据，还是修改指定文件。
5. 哪些文件明确禁止修改。
6. 本批目标数量，例如先做 5-10 条 sample 或 10-20 条批次。

除非用户明确要求，不直接扩全量。优先提交少量高质量样本供人工检查，通过后再继续扩充。

### 3.2 解析原始资料

PDF 与 MinerU JSON 同时存在时：

- PDF 用于人工查阅、视觉核对和物理页码确认。
- MinerU JSON 用于提取正文、标题层级和 `page_idx`。
- 优先使用具有正确阅读顺序的 `para_blocks`；缺失时再使用 `preproc_blocks`。
- 不得同时无条件拼接 `para_blocks` 和 `preproc_blocks`，否则可能造成正文重复。
- `discarded_blocks` 通常不进入正文，但可以用于读取页码、页眉和版面辅助信息。
- 递归读取 block、line、span 中的 `content` 时，应保持原始阅读顺序。

DOCX 输入时：

- 按段落顺序读取。
- 识别目录区与正文区，目录不得混入正文 chunk。
- 使用章、节、小标题建立章节路径。

### 3.3 先清洗，再切片

不得先按固定长度机械截断，再尝试修复语义。正确顺序是：

1. 去除版面噪声。
2. 恢复跨页或跨段的完整句子。
3. 识别标题层级和主题边界。
4. 按完整知识点切片。
5. 生成元数据和 citation。
6. 进行结构、正文和引用验证。

## 4. 文本清洗规则

### 4.1 必须保留

- 原文事实、观点和论证关系。
- 人物名、组织名、事件名、会议名、文献名和制度名。
- 对知识点有必要作用的原文引文。
- 原文中的年份、日期和重要数字。
- 对理解上下文必不可少的承接句。

### 4.2 必须删除

- 目录内容。
- 页眉、页脚和独立页码。
- 出版信息、扫描水印、公众号水印和下载站信息。
- 重复出现的页眉标题。
- OCR 产生的乱码、无意义符号和异常字符。
- 因同时读取多套 MinerU block 而产生的重复正文。
- 跨页拼接产生的重复句段。
- 单独出现且破坏正文连续性的脚注正文。
- 脚注序号，如 `①`、`②`、`③`。
- 无意义的连续空格、制表符和异常换行。

### 4.3 允许修正

只允许进行不改变原意的技术性修正：

- 合并中文字符间的异常空格。
- 恢复跨页断开的句子。
- 合并 OCR 错误拆开的词语。
- 删除完全重复的句段。
- 修正常见且能够由原文明确确认的 OCR 字符错误。
- 统一全角、半角标点和空白。

### 4.4 禁止改写

- 不概括或扩写原文。
- 不把原文改写成自己的观点。
- 不补充来源中不存在的事实。
- 不为提高检索效果而在正文中堆叠关键词。
- 无法确认的 OCR 内容不得凭印象猜测，应回查 PDF；仍无法确认时应舍弃该句或记录问题。

## 5. Chunk 切片规则

采用标题层级驱动的语义切片，不使用单页切片或纯固定字符切片。

### 5.1 基本要求

- 每条 chunk 只表达一个主要知识点。
- chunk 必须能够脱离相邻 chunk 基本独立阅读。
- 同一小标题下的相邻段落可以合并。
- 不得把不同人物、事件或论点强行合入一条。
- 不得因 PDF 翻页截断完整句子。
- 跨页 chunk 应合并为完整内容。
- 不使用滑动窗口，不制造大段重叠正文。
- 不生成完全重复或高度重复的 chunk。

### 5.2 长度建议

- 目标长度：约 300-700 个中文字符。
- 一个完整知识点不足 300 字时，可以保留较短 chunk。
- 一个知识点超过 700 字时，在自然段、论点、人物、事件或方法边界处分拆。
- 不得为了满足长度要求而截断句子或混入无关内容。

现有 demo 数据可作为风格参考，其正文通常约为 167-565 字，但新数据仍以语义完整为第一优先级。

### 5.3 跨页规则

- 跨页句子必须合并。
- `citation.page` 填 chunk 正文开头所在的 PDF 物理页。
- 不填正文结束页。
- 如果正文开头位于上一页末尾，即使主体内容在下一页，也必须填写上一页。

### 5.4 去重规则

至少检查：

- `text` 完全相同。
- 清除空白和标点后正文相同。
- 一个 chunk 的绝大部分正文被另一个 chunk 完整包含。
- 新批次与已有 demo、历史批次之间是否重复。

内容交叉但服务于不同完整知识点时可以保留；完全重复正文必须删除。

## 6. 标准化 JSONL Schema

每行必须是一个独立、合法的 JSON 对象。所有记录共用以下顶层字段：

```json
{
  "id": "chunk_sizheng_v1_001",
  "source": "中国共产党思想政治教育史",
  "source_type": "textbook",
  "title": "马克思学说在中国的最初传入",
  "text": "清洗后的完整正文……",
  "chunk_type": "textbook_chunk",
  "time": {
    "start": null,
    "end": null,
    "display": "第一章 中国共产党成立与思想政治教育的历史开端 / 第一节 马克思主义的最初传入与广泛传播 / 一、马克思学说在中国的最初传入"
  },
  "location": {
    "name": null,
    "lng": null,
    "lat": null,
    "coord_sys": null
  },
  "entities": [
    "马克思主义",
    "中国共产党"
  ],
  "tags": [
    "教材切片",
    "思政知识库v1",
    "马克思主义传入"
  ],
  "topic": "马克思主义在中国的早期传播",
  "citation": {
    "doc": "中国共产党思想政治教育史",
    "section": "第一章 中国共产党成立与思想政治教育的历史开端 / 第一节 马克思主义的最初传入与广泛传播 / 一、马克思学说在中国的最初传入",
    "page": 22
  }
}
```

### 6.1 顶层字段约束

| 字段 | 类型 | 是否必填 | 规则 |
|---|---|---:|---|
| `id` | string | 是 | 全文件唯一，稳定且可读 |
| `source` | string | 是 | 原始资料的正式书名或文档名 |
| `source_type` | string | 是 | 数据来源类型 |
| `title` | string | 是 | chunk 的短标题 |
| `text` | string | 是 | 清洗后的原文正文 |
| `chunk_type` | string | 是 | chunk 内容类型 |
| `time` | object | 是 | 时间信息对象，未知值使用 `null` |
| `location` | object | 是 | 地点信息对象，未知值使用 `null` |
| `entities` | string[] | 是 | 非空实体列表 |
| `tags` | string[] | 是 | 非空标签列表 |
| `topic` | string | 是 | 单一、具体的中心主题 |
| `citation` | object | 是 | 来源定位信息 |

禁止缺少字段。未知信息必须使用 `null` 或规范的空语义结构，不得删除字段。

### 6.2 ID

推荐格式：

```text
chunk_<资料缩写>_<版本或批次>_<三位序号>
```

示例：

```text
chunk_sizheng_v1_001
chunk_sizheng_v1_002
```

规则：

- ID 必须唯一。
- 后续批次从现有最大序号继续递增。
- 不因标题微调而随意更换已经发布的 ID。
- 不使用中文、空格或随机 UUID 作为常规 chunk ID。

### 6.3 source 与 source_type

`source` 必须使用资料正式名称，例如：

```text
中国共产党思想政治教育史
```

禁止在正式来源名中加入处理过程描述，例如：

```text
中国共产党思想政治教育史（MinerU_docx整理版）
中国共产党思想政治教育史（OCR清洗版）
```

处理过程应写入批次 README，而不是污染 `source` 或 `citation.doc`。

常见 `source_type`：

- 教材：`textbook`
- 事件资料：`event_doc`
- 家书或书信：`letter`
- 题库：`exam`

### 6.4 title

`title` 应是该 chunk 的核心知识点标题。

规则：

- 优先使用真实章、节、小标题。
- 没有现成小标题时，提炼简短、忠实的知识点标题。
- 不直接复制一整段正文首句。
- 不使用超长标题。
- 建议 8-30 个中文字符，原则上不超过 45 个字符。
- 标题不能包含页码、脚注、正文解释或来源后缀。

### 6.5 text

`text` 必须满足：

- 是清洗后的原文，而不是摘要。
- 非空。
- 语义完整。
- 无目录、页眉、页脚、水印和乱码。
- 无明显跨页断句。
- 无重复句段。
- 不包含为检索而人工添加的关键词。

### 6.6 chunk_type

常见取值：

- 教材正文：`textbook_chunk`
- 历史事件：`event`
- 叙事或书信材料：`narrative`
- 题目及解析：`qa`

同一输出文件中应保持类型口径稳定。

### 6.7 time

统一结构：

```json
{
  "start": null,
  "end": null,
  "display": "章节路径或时间显示文本"
}
```

规则：

- 教材没有明确事件时间时，`start`、`end` 为 `null`。
- 教材数据的 `display` 可与 `citation.section` 保持一致。
- 明确到日期时使用 `YYYY-MM-DD`。
- 仅明确到年份时，可使用该年的起止日期，并在 `display` 写“YYYY年”。
- 不确定时间不得猜测。

### 6.8 location

统一结构：

```json
{
  "name": null,
  "lng": null,
  "lat": null,
  "coord_sys": null
}
```

规则：

- 没有明确地点时全部使用 `null`。
- `name` 只能填写正文明确涉及且对知识点有意义的地点。
- 不因正文偶然提到某地就一定加入地点字段。
- 经纬度未经可靠地理编码时保持 `null`。

### 6.9 topic

`topic` 表示该 chunk 的中心主题，只填写一个字符串。

好的示例：

- `马克思主义传播与建党初期思想政治教育`
- `抗日战争时期干部教育`
- `张闻天《党的宣传鼓动工作提纲》`

不推荐：

- `思想政治教育史`
- `教材`
- `党史`

规则：

- 主题应具体到阶段、人物、文献、事件或核心论点。
- 同一批次可以有多个 chunk 共用阶段主题。
- 对核心检索题具有独特意义的 chunk，可以使用更细的专属 topic。

### 6.10 entities

`entities` 必须是非空字符串数组。

可收录：

- 人物
- 组织
- 会议
- 事件
- 文献
- 关键理论
- 重要制度或政策

规则：

- 实体必须能够从正文直接确认。
- 只保留与当前知识点直接相关的实体。
- 不因为某个词在正文中偶然出现就加入。
- 不全局删除“中国共产党”“马克思主义”“思想政治教育”等基础实体，应按内容中心性判断。
- 不把完整正文句子当作实体。
- 不重复添加同义或包含关系极强的词。
- 建议每条 3-10 个高质量实体；内容简单时可以更少，但不得为空。

### 6.11 tags

`tags` 必须是非空字符串数组。

建议组成：

- 1-3 个公共管理标签，例如 `教材切片`、`思政知识库v1`、`batch01`。
- 2-5 个具有检索区分度的内容标签。

总量通常控制在 3-8 个。

规则：

- 标签应短、稳定、可复用。
- 不把宽泛词同时重复放入 `topic`、`entities` 和 `tags`，避免人为放大检索权重。
- 不给多个不相关 chunk 堆叠相同的专属关键词。
- 核心人物、文献或问题标签只应出现在真正相关的 chunk 中。

### 6.12 citation

统一结构：

```json
{
  "doc": "中国共产党思想政治教育史",
  "section": "完整章节路径",
  "page": 22
}
```

`citation.doc`：

- 必须与 `source` 对应。
- 使用正式资料名称。
- 不加入 MinerU、OCR、整理版等处理描述。

`citation.section`：

- 只能写章、节、小标题组成的章节路径。
- 层级之间使用 ` / ` 分隔。
- 不得写入整段正文。
- 不得使用被正文污染的超长“标题”。
- 章节路径必须与 chunk 内容所在位置一致。
- 章前概述可只写章标题。
- 节导语可写章标题和节标题。

正确示例：

```text
第一章 中国共产党成立与思想政治教育的历史开端 / 第一节 马克思主义的最初传入与广泛传播 / 一、马克思学说在中国的最初传入
```

错误示例：

```text
第一，马克思主义传播必须……随后李大钊又指出……（整段正文）
```

`citation.page`：

- 表示 PDF 阅读器中的 1-based 物理页码。
- MinerU 的 `page_idx` 是 0-based。
- 换算公式：

```text
citation.page = page_idx + 1
```

- 跨页 chunk 填正文开头所在的 PDF 页。
- 必须通过正文开头在 MinerU/PDF 对应页命中来确认。
- 不根据目录页码、相邻 chunk 或章节顺序猜测。
- 无法确认时填写 `null`，并在批次 README 中说明原因。
- 如果需要记录书本印刷页码，应放在检查报告或映射表中，不得混用为 `citation.page`。

对于《中国共产党思想政治教育史》当前版本，正文区间通常满足：

```text
书本印刷页码 = PDF 物理页码 - 14
```

该偏移只适用于已经核验的当前文件版本，不得直接套用到其他 PDF。

## 7. JSONL 文件格式

必须满足：

- 文件扩展名为 `.jsonl`。
- 编码为 UTF-8。
- 每行一个完整 JSON 对象。
- 一条记录不得跨多行。
- 行尾使用标准换行。
- 不添加数组外壳。
- 不添加 Markdown 代码围栏。
- 不在 JSONL 中写注释。
- 中文应正常保存，不得写成 `????` 或乱码。

正确：

```json
{"id":"chunk_001","source":"资料名","source_type":"textbook"}
{"id":"chunk_002","source":"资料名","source_type":"textbook"}
```

错误：

```json
[
  {"id":"chunk_001"},
  {"id":"chunk_002"}
]
```

## 8. 批次交付规则

新资料建议按批次处理：

1. 第一批先生成 5-10 条或 10-20 条 sample。
2. 人工检查正文、标题、section、page、entities、tags 和 topic。
3. 样本验收后再追加下一批。
4. 每批连续覆盖明确章节或页码范围。
5. 不在未验收时一次性扩展数百条。

正式数据文件放在：

```text
data/processed/<输出文件名>.jsonl
```

批次说明放在：

```text
team_deliverables/lizhuoyang/YYYY-MM-任务名/README.md
```

批次 README 至少说明：

- 输入资料。
- 本批章节和页码范围。
- 输出文件及实际条数。
- 清洗与切片方法。
- ID 起止范围。
- `citation.page` 口径。
- 跨页 chunk 情况。
- 页码为 `null` 的条目及原因。
- 与已有数据的关系。
- 修改了哪些文件。
- 是否影响主项目运行。
- 验证命令和结果。

## 9. 质量检查

### 9.1 结构检查

使用仓库现有校验脚本：

```powershell
python validate_jsonl.py data/processed/<输出文件名>.jsonl
```

必须保证：

- 文件存在且非空。
- 每行都是合法 JSON。
- 所有必填字段存在。
- `id`、`source`、`source_type`、`title`、`text`、`chunk_type`、`topic` 为非空字符串。
- `entities` 和 `tags` 是非空字符串数组。
- `citation.doc` 和 `citation.section` 非空。
- `citation.page` 为正整数或 `null`。

另外必须单独检查 ID 唯一性，因为当前基础校验脚本尚未自动拒绝重复 ID。

### 9.2 正文检查

逐条确认：

- 无页眉、页脚、页码和水印。
- 无目录内容。
- 无 OCR 乱码。
- 无 `????`。
- 无异常空格。
- 无重复句段。
- 无跨页断句。
- 每条只表达一个主要知识点。
- 标题与正文中心一致。
- 正文不是摘要或人工改写。

### 9.3 Citation 检查

逐条确认：

- `citation.doc` 与实际来源一致。
- `citation.section` 是准确章节路径。

- 无法确认的页码为 `null`，没有猜测值。

### 9.4 元数据检查

- `topic` 具体且与正文中心一致。
- `entities` 都能从正文确认。

- 不存在关键词堆叠。
- 专属人物或文献关键词没有泄漏到不相关 chunk。
- 宽泛词没有在多个字段中无意义重复。
